| **CRAB LIMIT** | 11 | 档位选择器 |

**下层子面板 —— 拨动 / 按钮**

`LEVEL/FOLLOW SLOPE`(5) · `HDG AUTO`(5) · `MANAGED`(4) · `SYNC ×3`(6) · `AP`(4)

### 4.2 模式词必须重新定义

| 客机 | 群玉阁 |
|---|---|
| LNAV / HDG | 位置保持 / 速度指令 |
| VNAV / ALT / **V/S** | 高度保持 / zRef 转换 —— **V/S 旋钮删除** |
| LOC / APP | 靠泊模式（另设） |
| A/THR | 阻尼器自动（不是推力管理） |

⚠ **必须删除 V/S 旋钮**：垂向是被动跟随 + 15 min 慢调，没有"垂直速度"这个可指令的量。放 V/S 旋钮会误导使用者以为能控升降率。

### 4.3 旋钮只能旋转的后果

推/拉功能全部外置：
- 航向旋钮"按下/拉出" → **纯目标选择器**；速率模式另设带盖 `YAW RATE`（仅 L2/L3）
- "按压接管" → 独立 `MANAGED` 按钮（手柄一动即转 MANUAL）
- "拉出同步" → 独立 `SYNC` 按钮 ×3

## 8. 操纵逻辑：CRAB / TRK / HDG

### 8.1 手柄坐标系 = **TRK 系**（不是 BODY，不是 WORLD）

> **手柄"前" = TRK 旋钮所指的那个方向（一个世界系固定角）**

| 场景 | "前"意味着 |
|---|---|
| CRUISE / TRANSIT | 沿航迹 |
| **BERTH** | **沿泊位轴**（正是舵工心智） |
| **HOLD + 转向** | TRK 保留上次值作为基准；想向北就把 TRK 设 000 再推 |
| PRECISION | 沿作业轴 |

**一个系、无开关、无灯、无模式。** 圆表上"手柄前推 = 朝 TRK bug 方向"，直接可读。CRAB 同时是：箭头↔lubber 夹角 = 手柄系↔机体系夹角 = ψ − TRK，三者自洽。

### 8.2 为什么不做"手柄非中立时禁止改 TRK"

物理限速方向是**反的**：

| v | ω_max | 转 90° |
|---|---|---|
| 22 m/s | 1.02 °/s | 88 s |
| **0.3 m/s（靠泊）** | **74.9 °/s** | **1 s** |

高速时物理自动限死；**低速时物理完全不限速——而靠泊恰是最不能让坐标系变的场景**。且"手柄前推 + 慢慢转 TRK"就是飞曲线的自然方式，禁止即废掉主操纵。

### 8.3 替代措施：TRK SET 按钮（已采用）

| 措施 | 说明 |
|---|---|
| **① TRK SET 按钮** | 转旋钮只写入**草稿窗**，按 SET 才执行。按钮做触觉确认，比旋钮阻尼容易得多 |
| **② TRK = 目标 + 限速回转** | \(\omega\le F_{avail}/(Mv)\)，随速度自适应；跟不上通告 `TRK SLEW LTD` |
| **③ 手柄坐标系跟随"已回转的 TRK"** | 飞行员感到坐标系连续旋转，**永不跳变** |
| **④ BERTH / PRECISION 下 TRK 绑定到作业轴** | 进近准备时一次选定，飞行中不是自由旋钮 |
| **⑤ 目标≠实际时通告** | `TRK SLEW` + TRK bug 画空心/闪烁 |

⚠ 若采用"禁止改 TRK"的硬规则，必须做成**"不生效 + 明确通告"**，绝不能"转不动却没提示"。

### 8.4 CRAB 与 CRAB LIMIT

\[
\text{CRAB} = \psi_{HDG} - \text{TRK}\quad(\text{正 = 航迹在艏向右侧})
\]

**与飞机蟹行的根本区别**：飞机是被迫（侧风下为保持航迹必须偏头）；群玉阁是**自由选择**（力恒竖直，偏航与平移彻底解耦）。**正因自由，才需限幅。**

| 模式 | 限幅 | **谁优先** | 理由 |
|---|---|---|---|
| **CRUISE** | OFF | — | 纯位移 |
| **TRANSIT** | ±30° | **TRK** | 偏离航迹 = 触地/碰撞风险 |
| **PRECISION** | ±10° | **HDG** | 吊装需宫殿对准；速度低 |
| **BERTH** | ±5° | **HDG** | 对接口/舷梯必须对齐 |

⚠ **系统绝不能默默执行与旋钮不一致的值** —— 必须通告 `CRAB LIMIT` + 显示实际可达值 + 被夹的 bug 画空心/闪烁。

**物理边界**：CRAB 的物理上限随风速收缩（22 m/s 时 79% 艏向可行，25 m/s 时 28%，28 m/s 时 9%）。CRAB LIMIT 取**模式档位与可行扇形中的更严者**。

**补充**：SPD < 0.5 m/s 时显示 `NO TRACK` 并隐藏 CRAB，但**不隐藏 TRK bug**（它仍是手柄基准），标注 `HOLD REF`。

### 8.5 HDG AUTO

**目标函数**：\(\;J = w_F\|F_{thr}\| + w_M|M_z|\) —— **不是"最小偏航力矩"，而是"最小推力"**。

**为什么**：实测偏航单独永远不会先失效（需 r_cp > 2L = 100 m > 半宽 60 m，不可能）；真正的瓶颈是"平移 + 偏航合成需求"顶到单台推力上限。**最优艏向 0° 峰值 1.06%W，最差 123° 2.19%W，代价 +106%。**

**确定方法**（建议叠加）：
- **A 离线标定**：稳定风中依次保持若干艏向，记录稳态 azimuth 指令（= 环境载荷直接测量），按相对风角拟合 Fourier 级数存表
- **B 在线极值搜索**：缓慢扰动艏向 ±3~5°（周期数分钟），测 \(\partial J/\partial\psi\)，沿梯度走向更优。艏向惯量巨大，慢回路可行

**约束**：服从 CRAB LIMIT；死区 + 迟滞（防"打猎"）；BERTH/PRECISION 下抑制；只给建议值 `OPT HDG`，由 PIC 采纳。

**失效**：单台 azimuth 失效 ⇒ 只剩 (fx, fy) 两个自由度，无法同时指定力与偏航力矩 ⇒ 艏向被动，通告 **`HEADING FREE`**。

## 10. 应急与 ECS

| 项 | 决策 |
|---|---|
| **受控着陆** | zRef 可用 ⇒ 1.5 m/s，749 m 需 **8.3 min**，群玉阁完好。**排检查单首位** |
| **应急下降** | = **旁路 τ**（不旁路速率限）；749 m 从 ~37 min 缩到 8.3 min；建议带盖 + 双人确认 |
| **撤离** | 仅在 zRef 失效（fail-frozen 卡住高度）时；**排在受控着陆之后** |
| **ECS 应急操纵站** | 远离主舰桥、靠近逃生通道；最小手动杆（推进器段）+ 净升力/水平度/姿态 + 通信 + 逃生启动；独立电源与通信 |
| **独立逃生系统** | 不依赖主能源、APU、姿态控制；重力/绳索下降或自带电瓶逃生舱 |
| **地面疏散** | 宫殿悬在港口上方 ⇒ 地面禁区与疏散路线应视为系统的一部分 |

### 五条硬性原则
1. **一时刻一操纵源**：选 L3 后，侧杆与速度手柄电气+机械锁定失效
2. **不可逆动作双确认**：PIC 授权 + FE 执行，物理位置独立 + 保护盖
3. **告警分级**：L3 时只保留 Warning 与关键 Caution，防告警风暴
4. **物理分离**：ECS 独立电源与通信
5. **长期值守人因**：低噪声、可调座椅、夜航照明、值班轮换（悬停几乎不耗能 ⇒ 驻留极久）

## 11. 决策理由（摘要）

1. **驾驶舱按舰桥而非飞机做** —— 常态是长期驻留，核心矛盾是"几人长时间盯着一堆慢系统并在异常时正确接管"。
2. **取消连续姿态操纵** —— 弹簧自动保持水平/随坡倾斜（免费 2.42°），推进器倾斜需 5~19 倍权限。姿态界面退化为 `FOLLOW SLOPE / LEVEL` 两位开关。
3. **配平轮升格为主飞行控制** —— 推进器垂向只有 ±6 cm，zRef 是唯一高度手段；故配**升降计划显示**（像电梯楼层键而非油门）。
4. **手柄系 = TRK 系** —— 同时解决显示一致性、靠泊心智（沿泊位轴）、HOLD 转向三个问题；一个系、无开关、无灯。
5. **不用指示灯表达模式** —— 灯擅长告警不擅长表达状态；"灭灯"二义；让显示**自明**（看卡片顶端即知模式）。
6. **TRK SET 按钮而非旋钮阻尼** —— 可变阻尼难做且会漂移；二值门控（草稿窗 + SET）触觉确认更容易实现且更可靠。
7. **升限余量表放最显眼处** —— 它直读"还能坏几块石头"，是全舱唯一生死攸关的信息。
8. **受控着陆优先于撤离** —— 新模型下 zRef 可用即可安全着陆（1.5 m/s），比撤离远优；这修正了旧中性浮力模型下的结论。
